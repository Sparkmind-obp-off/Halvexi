# Roadmap and Acceptance Criteria

## Phase 0 — Blueprint
Documentation links work; prohibited behaviors, evidence rules, and approval gates are clear. Choose one initial product category and verify account/program eligibility.

## Phase 1 — Evidence ledger
Create candidates, attach source URLs/excerpts/timestamps, show missing/stale fields, export records. Acceptance: factual fields have provenance or are explicitly unknown.

## Phase 2 — Eligibility/economics
Record official program terms and verification date; implement explainable score and hard stops. Acceptance: unknown never silently becomes zero; score cannot override a hard stop.

## Phase 3 — Content package
Generate brief, scripts, shot list, caption, disclosure, CTA, and claim ledger. Acceptance: unsupported factual claims are blocked or removed.

## Phase 4 — Approval/publication record
Versioned human approval and manual publication checklist. Acceptance: unapproved or modified drafts cannot be marked approved/published.

## Phase 5 — Measurement
Import/enter metrics and compare experiments. Acceptance: observed, estimated, and unavailable data are distinct.

## Phase 6 — Controlled automation
Only after the manual loop works: scheduled evidence refresh, draft queue, authorized read-only analytics. Publishing API is considered only after current permission and policy verification. Acceptance: pause switch, limits, audit logs, retries, and revocation tested.

## Phase 7 — Multi-channel scale
Add channels with legitimate distinct purpose, accountable owner, policy check, and measurement. Acceptance: each channel's permissions, disclosures, ownership, and incidents are auditable.

Build order: prototype workflow → operator validation → freeze requirements → evidence ledger → real product loop → measured expansion. Do not build a generalized autonomous agent platform before the first repeatable loop.
